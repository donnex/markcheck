# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `Ctrl-L` redraws the whole screen, as in vim, less and the shell. Anything written to the terminal behind markcheck's back, such as a background job started from the same shell, a `wall` broadcast or console messages, stayed on screen over the cards until those cells happened to change, and `Ctrl-L` was rejected as `Ctrl-L is not bound`, so the only fix was resizing the window or `Ctrl-Z` then `fg`. It works on every screen and overlay and leaves everything else as it was. (#205)
- `--no-terminal-title` and `--no-exit-summary` turn off the terminal title and the line printed after quitting for one run, and `--terminal-title` and `--exit-summary` turn them back on over a config file that sets `terminal_title = false` or `exit_summary = false`. These two settings could only be changed in the config file, although the 1.3.0 notes and the README said every on/off setting has a flag in both directions, so a shared config that turned the exit line off couldn't be overridden, and there was no way to leave the title alone without writing a config file. (#163)

### Fixed

- A checklist with a very long unbroken stretch of URL-like text, such as `(http://` repeated thousands of times or a link followed by tens of thousands of `)`, no longer freezes markcheck for seconds when it opens the file and again on every reload. Looking for plain web addresses to turn into links rescanned the rest of the stretch for every place a link could start, so the time grew with the square of its length. (#246)
- A markcheck killed while git sync was running a git command, by `kill -9`, the out-of-memory killer or a crash, no longer leaves that command's output in the temp directory for good. Each git command's input and output go through small private files there, which hold branch and remote names, commit subjects and repository paths, and only a normal exit removed them, so they built up over time. The next start now removes the ones your own killed sessions left, after the same 15-minute wait as the other leftovers, and counts them in its `removed N files left by an interrupted markcheck` note. (#243)
- Renaming the `##` heading of the list you are working in, or fixing a typo in it, no longer loses your place when the file reloads. markcheck looked for your list only by its old heading, so after the edit it put the cursor on the first task of the document and reported every task under that heading as removed and added again, as in `Reloaded: 2 added · 2 removed — task not found, cursor moved`, although no task had changed. The cursor now stays on the same task under the new heading and the reload reads `Reloaded: file changed on disk`; the same holds when tasks written before any heading get one. When the task itself is gone too, the cursor moves to the nearest task rather than to the top. (#242)
- A quote above a section's first task now keeps everything written inside it, in order, above that task's card. A heading inside the quote was dropped, a command inside it was shown before the text that says when to run it, and a bullet inside it hid the whole quote: in a callout such as `> [!WARNING]` / `> Take a snapshot first:` with the command in a quoted fenced block, the command appeared on its own above the warning, and the warning's text before and after it ran together. The quoted heading is now a line of the quote, a quoted bullet a `- …` line, and the command sits between the text before and after it. (#241)
- `o` on a link to a heading in the same file, such as `[the notes](#notes)`, now says `#notes has no tasks: nothing to jump to` and stays put when that heading has no task of its own, and `markcheck runbook.md#notes` opens at the start with `#notes has no tasks`. Before, markcheck moved to the first task of whatever section came next and reported `Jumped to #notes`, so a runbook link such as "if the health check fails, see Rollback" to a section written as prose, or with steps that had no checkboxes, landed on a step of a different section while the status bar said the jump had worked. A link now only reaches tasks before the next heading of the same or a higher level, so a `##` section still includes the tasks of its `###` sub-sections. (#240)
- The `T` "go to task" list now opens on the task you are on, and marks it with `❯` so you can find it again after moving the highlight. It always opened at the first task of the document with that one highlighted and nothing marking where you were, so on a long runbook it showed the wrong end of the list, and an `Enter` pressed by reflex threw you back to the first task, which `Ctrl-O` couldn't undo. `Enter` on your own task now just closes the list (`Already on this task`), and typing or deleting in the filter highlights the first match at or after your task, as `/` does, rather than the first in the document. (#239)
- `Ctrl-Z` now says so when there is no shell to suspend to, instead of flashing the screen and reporting `Resumed`. Started straight from a terminal, a tmux window or pane, `ssh -t` or `exec`, markcheck has no job-control shell behind it, so the system ignores the stop: the screen blinked, nothing was suspended, and the status bar claimed it had resumed. It now stays on screen with `Can't suspend: markcheck wasn't started from a shell with job control (q quits)`. (#238)
- A key that isn't bound on the checklist screen now says so in the status bar, as unbound `Ctrl` and `Alt` chords and the completion screens already did, instead of doing nothing: `F1 is not bound (? lists every key)`. The 1.3.0 notes promised this, but on the checklist screen a key such as `x`, `Home`, `End`, `Delete` or `F1` did nothing at all and cleared the message you were reading, so the keys a new user tries first gave no hint of the right one. `x` now adds `Space checks a task`, and `Home` and `End` point at `gg` and `G`. A `0` typed right after `o` or `y` on a card with several links or commands likewise reports `No link [0] on this card` or `No command [0] on this card` instead of silently cancelling. (#229)
- A link whose text is bold, such as `[**Dashboard**](https://example.com)`, at the start of a task or note now shows on the card as that link. markcheck took the bold text for the card's title instead, so the title read `Dashboard` with no sign it was a link, the link itself was drawn with no text at all, and on a card with several links its `[1]` marker stood alone with nothing in front of it. (#228)
- An image in a task or note now shows on the card as an underlined `image: <alt text>` link (just `image` when it has no alt text), with its address listed below the card, and `o` opens it in your browser. Before, only the alt text was shown as plain words and the image's address was dropped, so a step pointing at a screenshot of what you should see gave no sign there was a picture, `o` said `Nothing to open: card has no link`, and an image without alt text left no trace on the card at all. (#227)
- Three common first-run mistakes now say how to fix them instead of ending in a bare system error. Opening a checklist that doesn't exist yet printed `cannot resolve path: notes.md` with `No such file or directory (os error 2)` and now reads `no such file: notes.md (create it with markcheck --new notes.md)`; `--new` on a file that is already there printed `File exists (os error 17)` and now reads `notes.md already exists (open it with markcheck notes.md)`; and `e` on a machine without `vi`, with neither `$VISUAL` nor `$EDITOR` set, said `Failed to launch vi: No such file or directory` and now says `vi not found — set $EDITOR (or $VISUAL) to your editor`. (#226)
- `o` now works with a text-mode browser such as `w3m` or `lynx` in `$BROWSER`. markcheck started every browser in the background with no terminal, so `w3m` printed the page to nowhere and exited while the status bar said `Sent to w3m: <url>`, and `lynx` or `links` failed or hung out of sight. That left no way to open a link on a server reached over SSH, where a text browser is often the only one, or with `BROWSER=firefox:w3m` wherever Firefox is missing. A text browser now gets the whole terminal, the way `e` hands it to your editor, and markcheck comes back with `Back from w3m: <url>` once you quit it. (#225)
- With git sync on, markcheck now refuses to commit when `user.name` or `user.email` is not set for git, and says so at startup: `Git sync: no git identity set — commits will be refused; set git config user.name and user.email`. On a fresh machine or a server account where they were never set, git made an identity up from the account and host name, such as `root@` the server's name, and said so only in output markcheck didn't show, so the commits went out to the shared repository under that name without notice, and a pushed commit can't be re-attributed. Each refused sync now ends with the same `set git config user.name and user.email` hint, in the status bar and on exit; the file itself is still saved. Where git couldn't make one up, every sync already failed, with `empty ident name … not allowed`, which didn't say how to fix it.

  `GIT_AUTHOR_NAME`/`GIT_AUTHOR_EMAIL` and `GIT_COMMITTER_NAME`/`GIT_COMMITTER_EMAIL` count as set; the `EMAIL` environment variable alone does not, following git's own `user.useConfigOnly` setting. (#224)
- With `NO_COLOR` set, error messages now stand out from confirmations. A failed save, a reload that dropped your change, a git sync problem, the search's `(no matches)` and the `T` picker's `No matching items` were told apart only by their red color, which `NO_COLOR` turns off, so `Write failed — change not saved to disk` looked just like `Copied to clipboard`. They are now drawn in bold reverse video. (#223)
- Clicking a task's row in the overview panel now checks or unchecks it only when you click its state icon, as the README describes. The panel border, the indent and the `│` depth guides to the left of the icon toggled the task too, so a click there meant to select the task changed its state and saved the file, and with git sync on committed and pushed it. Those columns now jump to the task like its label does. (#222)
- A task written with an uppercase `[X]` is now saved as `[x]` when you uncheck it and check it again, as the README describes. markcheck compared against the file as it was first opened rather than as it last saved it, so the task went back to `[X]`. (#221)
- A browser that `o` starts no longer closes when you close the terminal markcheck runs in. The browser shared markcheck's terminal job, so closing the window or tab, or a dropped SSH or terminal session, sent it the same hangup and closed it with every tab opened since, and `Ctrl-C` while `e` had your editor open reached it too. It showed up only when the browser wasn't already running, so `BROWSER=firefox` lost its windows seemingly at random. Text browsers such as `w3m`, which take over markcheck's terminal, are unchanged. (#233)
- GitHub's `> [!NOTE]` and `> [!TIP]` quotes in the prose above a task now show their label (`Note: …`, `Tip: …`) instead of the raw `[!NOTE]` marker, as a plain quote rather than in the warning color, and the alert markers are recognised in any case, so a `> [!warning]` gets the warning color like `> [!WARNING]`. Before, only upper-case `[!WARNING]`, `[!CAUTION]` and `[!IMPORTANT]` were recognised: a runbook written for GitHub showed a note or tip starting with literal bracket syntax, and a lower-case warning lost the warning color it relied on. (#220)
- Starting markcheck no longer deletes the temporary files of another markcheck that is still saving or syncing the same checklist out of its sight: on another machine sharing the folder over the network, in a container sharing the checkout, or as another user on a system that hides other users' processes. At startup markcheck removes the files an interrupted markcheck left behind, and it took any whose process it couldn't see for abandoned, so the other session's save failed with a wrong `the file or its folder no longer exists`, and its git sync could build a commit that deleted every other file in the repository, then undo it and wrongly blame a commit hook. Only your own files at least 15 minutes old are now removed, which no live save or sync keeps that long. (#218)
- With git sync on, a second `SIGTERM` or `SIGINT` sent while markcheck waits for a running sync to finish no longer leaves the terminal unusable and a `git commit` running behind it. markcheck exited on the spot: the shell behind it echoed nothing and printed escape codes on every mouse move until you typed `reset`, the commit still landed on the branch after markcheck was gone, unpushed and with the staging area out of step, and its temporary files were left in the repository. This is exactly what an impatient `kill`, `timeout` or a service manager sends. Now the second signal stops the sync's `git` processes at once and cleans up after them, restores the terminal, and exits with status 1 and `stopped by a second signal`; only a third signal still exits on the spot. A signal sent while `Ctrl-Z` waits for a sync now quits instead of suspending. (#217)
- A checklist with a long chain of nested started (`[/]`) or skipped (`[-]`) tasks no longer freezes markcheck on opening. Where a task holding only its marker had an ordered sub-list starting at 2 under it, and that sub-list's task did the same, markcheck read the whole file again for every level, so a file a few megabytes long, such as one crafted or generated by someone else, could take more than a minute to open and froze the screen for as long again whenever the file changed outside markcheck. Such a chain is now recognised to 8 levels deep, far past what a real checklist needs, and deeper markers are shown as text. (#216)
- `markcheck --version` built from a source tarball now shows `unknown` for the commit instead of a commit from some other project. When the source was unpacked inside another git repository, such as a distribution's packaging repository, a monorepo or a home directory kept in git, the version line carried that repository's latest commit, which doesn't exist in markcheck's history and so pointed a bug report at the wrong code, and every commit to that repository rebuilt markcheck. The commit is now shown only when building from a markcheck checkout itself. (#214)
- The startup warning that a checklist is `already open in another markcheck` no longer appears for a session that no longer exists. A markcheck killed outright, by the out-of-memory killer, a power loss or a reboot, leaves its record behind, and once its process number was reused by an unrelated program, which after a reboot is quite likely, every start of that checklist showed the warning for as long as that program ran, teaching you to ignore it. markcheck now records which process opened the checklist, not only its number, and drops the record when the number belongs to someone else. How long the other session has been open now reads in hours or days once it is long, such as `opened 3 days ago` instead of `opened 4320 min ago`. (#213)
- With git sync on, markcheck no longer skips its git cleanup when it exits with an error because the terminal went away, such as a closed window or dropped SSH connection that broke a screen update before the hang-up signal arrived. A change still waiting out the quiet period was left uncommitted, to be committed later under an unrelated change's message; a `git commit` or `git push` already running could keep going after markcheck had exited; and nothing said the change hadn't been published. It now syncs the waiting change, waits up to 5 seconds for a running sync before stopping it, and prints the usual `markcheck: git sync …` line if anything is left unpublished, as it does on `q` or a closed terminal. (#212)
- With git sync on, quitting after a sync had already failed now says so after the screen closes. The `markcheck: git sync failed: …` (or `committed but not pushed`, or `not tracked in git`) line was printed only for a sync that ended while markcheck was quitting, so a failure shown a few seconds earlier, with nothing left running at `q`, left the screen with no message, and the change could be left uncommitted without notice. The line now reports any problem that no later sync has resolved, also when markcheck is closed by `SIGTERM` or a closed terminal. (#211)
- With git sync on, answering the question shown when quitting a finished checklist now closes it. While markcheck waited for the last sync before exiting, the question stayed on screen, still offering to reset tasks that `y` had just reset and saying `Press Esc to keep working`, though `Esc` only repeated the waiting message; it looked as if the answer hadn't registered, and a second `q` would abandon the sync. The checklist now shows behind `Waiting for git sync… press q again to abandon`. (#210)
- Pressing `q` twice now quits a finished checklist. With every task done, `q` asks whether to reset the tasks before quitting, and a second `q` closed that question and went back to the checklist, so each `q` opened and closed it in turn and markcheck looked stuck. `q` in that question now quits without resetting, like `n`, and the question says so; `Esc` still goes back to the checklist. (#209)
- The startup warning for a checklist that belongs to another user no longer promises that saving will work when it won't. It always said `this file belongs to user N — saving makes it yours`, so in a folder owned by that user, or on a read-only mount, the first toggle came as a surprise: `Write failed — change not saved to disk: no permission to write the file or its folder`, on every toggle after it too. It now says `you can't save this file (no write permission) — changes won't be saved` there, so you can quit before you start, and names the owner by user name where there is one. (#208)

  In a shared sticky folder (`chmod +t`, like `/tmp`), another user's checklist that you may write was refused outright, although the file itself could be written. It is now saved in place, keeping its owner, the warning says `changes will be saved in place, so it stays theirs`, and the first save shows the `Saved in place` notice.
- Over SSH, `o` now also copies the link when it opens it with `xdg-open` or `open` on the remote machine. With a display set there, such as a tmux session started at a workstation's desktop and reattached from a laptop, or a Mac with someone logged in at its screen, the page opened on that machine's screen instead of yours, while the status bar said `Sent to xdg-open: <url>` as though it had worked. The link now also goes to your own terminal's clipboard through OSC 52, and the status bar says so: `Sent to xdg-open on this host: <url> · link also copied (system clipboard + OSC 52)`. Setting `$BROWSER` still opens links without copying them. (#207)
- With git sync on, `Ctrl-Z` no longer holds back a step you just checked until you come back with `fg`. A stopped markcheck can't commit or push, and a change made just before `Ctrl-Z` was almost always still waiting out the 10-second quiet period, so anyone following the same checklist through git saw the step as not done for as long as you stayed in the shell, with nothing saying so. markcheck now commits and pushes it first, showing `Waiting for git sync before suspending…` for up to 5 seconds; a sync that takes longer finishes after `fg`, and the shell shows `markcheck: git sync paused while suspended; fg to finish it`. (#206)
- A checklist saved in place, in a folder where markcheck can't create a temp file, is no longer destroyed when that save fails. The file was emptied before the new content was written, so a full disk, a used-up quota or an I/O error on a network share part-way through left it empty or cut short, while the status bar said `no permission to write the file or its folder`, as though nothing had been written; the next reload could then adopt the cut-down file. The new content is now written over the old without emptying it first, so a failed save leaves a whole checklist, and the message names the actual failure, such as `the disk is full`. (#199)
- With git sync on, a tick no longer pushes an empty commit you made yourself and haven't pushed yet, such as one from `git commit --allow-empty -m "trigger deploy"`. It was published along with markcheck's own commit, possibly starting a pipeline or deployment you meant to start later. It now blocks the sync like any other unpushed commit of yours: `Git sync failed: commit abc1234 "trigger deploy" is not pushed yet and isn't markcheck's; push or drop it first`. (#198)
- A `[/]` or `[-]` that isn't a checkbox is now shown as written. Where it followed the `#` of a heading inside a bullet, as in `- # [-] Wait for the rollout`, or opened the line after an empty `-` bullet, the note card, the overview, the `T` picker and `/` search all showed it as `[ ]`, so a skipped or in-progress step read as an open checkbox and searching for `[-]` missed it. The file itself was never changed. (#197)
- Links to a heading, such as `[Rollback](#rollback)` followed with `o` or `markcheck runbook.md#rollback`, now find the same headings GitHub does. Three kinds said `No section named #… in this file`: a link copied from a browser for a heading with an accented letter, such as `#d%C3%A9ploiement` for `## Déploiement`; a link to a heading inside a list item, such as the note `- ## Rollback`; and a numbered repeat such as `#verify-1` when an earlier `## Verify` was inside a `>` quote, which GitHub counts and markcheck didn't, so `#verify` also landed on the wrong one. All three now work, and a heading inside a list item jumps to its own card. (#186)
- `markcheck --new notes.md` run without a terminal, such as piped into another command or from a script, no longer creates the file. It created `notes.md` and then exited with `markcheck is interactive and needs a terminal`, so running the same command again from a terminal failed with `File exists`. It now exits with `cannot create notes.md: markcheck is interactive and needs a terminal` and leaves nothing behind. (#182)
- A message raised while `/` search is open is now shown. While you typed a search, the status bar showed only the search prompt, so a reload summary such as `Reloaded: 2 done, 1 reopened` timed out unseen, and a failure that is meant to stay until read, such as `File was deleted — changes cannot be saved` or `Git sync failed: …`, was cleared by the next key of the query without ever appearing. Such a message now appears on its own row above the search prompt and stays while you type; `Enter` adds the match position after it instead of replacing it, and `Esc` leaves it showing. (#181)
- With git sync on, saving the checklist from another editor within the git sync wait after a tick no longer turns the title bar red. The tick waiting to be committed was still committed once the wait ran out, found the file changed, and failed with `Git sync failed: the file changed after this sync was queued, so it was not published`, although markcheck is meant to drop a waiting sync when the file is changed outside it. The waiting sync is now dropped, and the reload message says so, as in `Reloaded: 1 done ("Verify") — pending git sync dropped`. A change saved in `e` still commits a waiting tick along with the edit. (#178)
- Moving past the first or last task with `h`/`j`/`k`/`l` or the arrow keys now says so: `Already at the last task` or `Already at the first task`, followed by `· Tab finds unfinished ones` while other tasks are still open. The key did nothing and showed nothing, so at the end of a long checklist you couldn't tell the end from a keypress that got lost on a slow connection. The mouse wheel still stops there without a message. (#176)
- With git sync on, an undo or redo is now committed under a message saying what it did, such as `checklist.md: Undo: Uncheck "Restart service"` or `checklist.md: Undo: 3 tasks ("Drain node", "Restart service", "Verify")`. It was committed as `Undo: 1 item` or `Redo: 3 items`, so someone reading the shared history couldn't tell which step had been reopened without comparing the file's versions, although every other change names its task. (#175)
- The reset dialog's status-bar line now lists only the keys it accepts. After `R`, it always read `y:all  l:list  s:sub-list  any other key:cancel`, even on a checklist with a single list or on a task outside any sub-list, and pressing the advertised `s` there just closed the dialog without a word. `l` and `s` now appear only when the dialog offers them, and `s` outside a sub-list keeps the dialog open with `No sub-list here: y resets everything`. (#174)
- Opening a checklist at a section or line, as in `markcheck runbook.md#rollback` or `markcheck +120 runbook.md`, now always confirms with `Opened at #rollback`. The confirmation was dropped whenever there was also a startup warning, such as text the checklist can't show or the file being open in another markcheck, so a successful jump looked the same as starting at the top. And a tick after a checklist was edited down to no tasks no longer says `File changed on disk — reloaded; change not saved, please retry`: nothing had been reloaded and retrying could never work, so the status bar now keeps saying `Reload skipped: file has no checklist items — changes cannot be saved until it has tasks again`. (#168)
- The terminal title is now right while you are in your editor or the shell, and after you come back. While `e` had the editor open or `Ctrl-Z` had you in the shell, the tab still read `Deployment Runbook · 3/11 — markcheck`, and after the editor or shell set a title of its own markcheck didn't set its title again until the next tick changed the count, so the tab named the wrong thing. Your own title is now shown while the other program has the terminal, and markcheck's comes back as soon as it takes the terminal back. (#162)
- Over SSH, copying a command too large to send through the terminal (OSC 52, over 70 KB) no longer says `Copied to clipboard`. Only the system clipboard got it, and over SSH that may be another machine's, so pasting on your own machine gave the previous contents after markcheck said the copy worked. The status bar now says `Copied to the system clipboard only — too large to send through the terminal (OSC 52)` and keeps the message until the next key, for `y`, `--auto-copy` and a link copied by `o`. (#161)
- A git sync failure now stays in the title bar on a terminal narrower than 80 columns, such as a split pane or a phone. Below that width the whole `⇅ git` section was dropped, so a failed push or an untracked checklist showed only as a status-bar message that cleared on the next key, and nothing on screen said afterwards that the checklist was `not pushed`. The section is now shown at every width; only its `Synced … ago` text is left out on a narrow terminal. (#160)
- Tasks written before a checklist's first heading are no longer listed under the made-up name `(Default)`. Once the file also had a `## Heading`, that name showed in the overview, the list tabs, the `T` picker, the list-complete screens and the `Tab` wrap message, and resetting that list with `R` then `l` said `"(Default)" reset to not done` and, with git sync on, committed `Reset "(Default)" to not done` to the shared history. The list now takes the checklist's title, its `# Heading` or, without one, the name made from the filename (`quick-tasks.md` shows `Quick Tasks`). (#159)
- `markcheck --help` and `man markcheck` now cover everything needed without the README. Both now say that `markcheck runbook.md#rollback` opens at a section and `markcheck +120 runbook.md` at a line, which only the README mentioned. The man page gains an ENVIRONMENT section listing the variables markcheck reads (`NO_COLOR`, `TERM`, `EDITOR`, `BROWSER` and others) and an EXIT STATUS section. And `--git-sync`'s help no longer says it commits after every toggle: changes are committed once `--git-sync-delay` passes with no further change. The README's install section also gains `cargo install --git https://github.com/donnex/markcheck` and a `git clone` for building from source on other platforms. (#173)
- Pressing `s` now confirms in the status bar with `Marked started` or `Marked not started`, as `Space` and `-` already did. It was the one task-state change that said nothing, and since `s` toggles, pressing it a second time silently undid it; with no color, where a started task differs only by a small `◐`, there was no sign the key had done anything. (#158)
- Git sync no longer publishes checklist edits you never asked it to sync. A tick committed and pushed the whole file under its own `Check "…"` message, so an uncommitted draft step, a local note, an edit another editor or script made, or an `e` edit you aborted with an error went to the shared remote the moment you ticked an unrelated task, with nothing in `git log` to show it. A tick now syncs only markcheck's own changes: when the file holds changes markcheck didn't make, nothing is published and the status bar says `Git sync failed: the checklist has changes markcheck didn't make, so nothing was published; commit them yourself, then toggle again`. Staging the checklist before ticking still syncs as before, an edit saved in `e` is still synced, and after a sync refused for another reason (a merge conflict, a failing hook) ticking again still syncs your ticks. (#177)
- A `TMPDIR` that is missing or can't be written to no longer turns off markcheck's safeguards or blames git. markcheck found out which user it runs as by creating a file in the temp directory, so with a bad `TMPDIR` every save silently ran without the lock that stops two markcheck windows on one checklist overwriting each other's changes, and the warnings that a checklist belongs to another user or is already open in another markcheck never appeared. Git sync was also switched off with `Git sync off: git not found on PATH` while git was installed; the message now names the temp directory it couldn't use: `Git sync off: could not run git: cannot create git scratch files in <directory>: …`. `Ctrl-Z` and stopping a stuck git command also no longer need a `kill` program, so `Couldn't suspend: couldn't run kill` can't happen. (#154)
- The `?` keybinding help now says that `R` can reset just the current list or sub-list. It still described `R` as resetting every task, although the reset dialog has offered the list and sub-list too since that was added. (#152)
- A bullet list with no checkboxes is now counted in the startup note of what markcheck isn't showing. Such a list is dropped, and while paragraphs, quotes and code blocks markcheck can't show were already counted, the bullets were not, so a "before you start" section of plain bullets vanished without a word. The note now says, for example, `2 bullet points outside task lists not shown`. (#151)
- The reset confirmations now count skipped (`[-]`) tasks. Pressing `R` when the only changed tasks were skipped said `This marks  tasks (of 4) as not started`, and with done and skipped tasks it named only the done ones and left the skipped ones out of the total, although the reset clears them too; it now says, for example, `This marks 2 done and 1 skipped tasks (of 5)`. Quitting a checklist whose tasks are all done or skipped, including one where every task was skipped, now offers the reset as a fully done one does, instead of quitting with the `[-]` markers left in the file, and undoing or redoing a skip says `marked skipped` rather than `restored`. (#150)
- Copying now refuses a command containing a zero-width character, such as a zero-width space, word joiner, byte-order mark, soft hyphen or Unicode tag characters, or a variation selector with nothing before it to modify. The card doesn't show these, so `systemctl restart nginx` with a zero-width space inside it looked right but failed when pasted, and a host name or path could silently name something else. Such a command is now refused with `Not copied: command contains hidden control characters`, like one with an escape or a bidi override. (#149)
- A huge git sync wait no longer crashes markcheck on the first tick. A `--git-sync-delay` or config-file `git_sync_delay` too large for the clock, such as a huge number meant as "never commit on its own", saved the tick and then crashed, so the change was never synced, and with such a config file every session crashed the same way. The wait can now be at most 86400 seconds (a day), and a longer one is refused at startup with `git_sync_delay must be at most 86400 seconds`. (#147)
- The `?` keybinding help can now be read in full on an 80-column terminal. It shared the screen with the overview, so on the common 80×24 most descriptions were cut off mid-word with no way to scroll sideways to the rest. The help now uses the whole width while it is open, and a description that still doesn't fit wraps onto the next row. (#251)
- A second `# Heading` in a checklist now starts a list of its own, like a `## Heading`. Before, it started nothing: its tasks joined whatever list came before it, and its name was shown nowhere, so a runbook split into `# Upgrade`, `# Verify` and `# Rollback` counted the rollback steps as part of the upgrade, and wasn't complete until they were done too. The first `# Heading` is still the title. (#250)
- A task with a long code block or command no longer freezes markcheck or runs it out of memory. Each row of the block on the current card kept its own copy of the whole block, and a long command was re-measured from its start for every row it wrapped onto, so a 10,000-line block took over three seconds and well over a gigabyte to draw on every key press, and a few hundred kilobytes could exhaust memory as soon as the checklist opened. Such a card now draws in a fraction of a second. (#245)
- A checklist that repeats the same heading many times, such as a `### Verify` under every host, no longer takes minutes to open. Each repeat checked every earlier heading once per number it tried for its link name, so 3,000 repeats took most of a minute before anything was shown, and the screen froze for as long again every time the file changed on disk. Such a file now opens at once. (#148)
- Git sync no longer takes a commit made on top of its own for its own and rewinds it off the branch. A `post-commit` hook that commits a follow-up (a regenerated file, an auto-changelog) lost that commit on every sync, as could a commit you made in another terminal at the same moment, which left the branch and reappeared as staged changes; the status bar then claimed markcheck's own commit had been undone, when it was the one still there. Both commits now stay on the branch, nothing is pushed, and the status bar says another commit landed on top of markcheck's. (#232)
- Holding `Space` or pressing it twice quickly no longer walks past a critical step (a task whose bold title starts with `!`). The confirming press could come at any speed, so a held key's repeats armed and confirmed the step in a fraction of a second, despite the release notes promising otherwise; `-` didn't ask at all, so a held `-` skipped every critical step in a list. The second press, of `Space` or `-` alike, now has to come after a short pause, and a quicker one keeps the step open and says it was too quick. (#219)
- The list title, the list's banner and a task's notes and `> [!WARNING]` alerts above it no longer vanish when a task's card is tall. On a short terminal, such as the common 80×24, a long, command-heavy step hid every row above its card at once, with nothing saying anything was hidden, so a "take a backup first" warning disappeared on exactly the step it was written for. The card now gets shorter instead (its text scrolls), and only when even the shortest card leaves too little room are rows left out: first the sub-section name and list title, then notes from the end, with the banner and alerts kept the longest and a `…` marking the cut. (#180)
- Git sync no longer draws a GPG passphrase prompt over markcheck. With signed commits (`commit.gpgsign`), a key whose passphrase wasn't cached and a terminal pinentry such as `pinentry-curses`, the first sync after a tick opened a full-screen passphrase dialog on top of the checklist, and your keystrokes were split between the two: part of the passphrase could be taken as markcheck commands, and when the dialog closed the screen was left garbled. Signing now fails at once with the reason in the status bar, as the README already said it would; a cached passphrase or a graphical pinentry keeps working. (#204)
- A critical step armed by clicking its marker in the overview now asks you to click it again, rather than to press `Space`. `Space` acts on the current card, not the clicked one, so following the old prompt checked a different task. Scrolling the mouse wheel or pasting now also leaves an armed critical step open; before, a wheel away and back hid the prompt but kept the step armed, so the next `Space` checked it in what looked like a single press. (#179)
- Git sync now says at startup when your git is too old for it, instead of appearing to work. It needs git 2.22 or newer, not git 2.0 as the README claimed; with an older git, such as the 2.17 or 2.20 still found on long-lived servers, every push was refused with a wrong reason ("`git push` would not push this branch …") and markcheck's own earlier commits were never pushed, so commits piled up locally. Git sync now stays off with `Git sync off: git 2.22 or newer is needed (found 2.17.1)`. (#169)
- Pressing your terminal's interrupt key while editing a checklist with `e` no longer ends markcheck. Emacs uses `C-g` as that key, and line editors such as `ed` use `Ctrl-C`; once markcheck quit as soon as the editor closed, and twice killed it straight away while the editor was still open, leaving the editor stranded with any unsaved work at risk. The key now goes only to the editor. (#146)
- The README no longer contradicts markcheck in several places. It said a card's 10th and later links couldn't be opened, although `o` opens them by typing both digits; it described three task states rather than four, leaving out skipped (`[-]`), and left skipping and the list and sub-list resets out of what undo and git sync cover; it said an indented code block outside a task was ignored, although under a heading it is shown above the first task like any other code block; and it said the exit status was always 0, although a second `SIGTERM` or `SIGINT` exits at once with status 1. Its git sync table now also lists the `⇅ git · pending` state shown while a change waits to be committed. (#153)
- Git sync now explains a failed sync correctly when your system language isn't English. With git's translations installed, a non-English locale made git print words such as `schwerwiegend:` instead of `fatal:`, so markcheck couldn't find the reason: the status bar showed the last hint git printed after a rejected push or refused commit, a checklist outside any repository showed git's raw text instead of `Git sync off: the file is not in a git repository`, and a push that lost a race was not explained as `the remote branch changed while pushing`. Git's messages are now always in English; the rest of your locale, such as the character set your hooks see, is unchanged. (#170)

### Security

- A checklist can no longer send escape sequences to your terminal through its title, a task's label or its file name. These were written to the terminal title, the line printed on quit and git-sync's messages without being cleaned, so a crafted checklist could, for example, silently replace your clipboard with a command of its choosing the next time you ticked a task or quit. Control characters are now dropped from all of them, and from git-sync commit messages. (#145)
- A relative `XDG_CONFIG_HOME` or `HOME` is now ignored when looking for the config file, as the XDG Base Directory specification requires. With `XDG_CONFIG_HOME=.config`, for example, markcheck read `.config/markcheck/config.toml` from whatever directory you ran it in, so the settings changed from one directory to the next, and a project or unpacked archive carrying that file could turn git sync on for the checklists opened from it. markcheck now falls back to `~/.config/markcheck/config.toml`, and reads no config file when `HOME` is relative too. (#234)
